# Дополнение к лабораторной работе №2

## Постраничный вывод
Таблица показывает не более 100 строк на странице. Фильтры и поиск пересчитывают выборку, а кнопки «Назад/Вперёд» меняют страницу. Во время сканирования интерфейс обновляется раз в 25 результатов, а не на каждый файл.

## Разрешение
- JPEG: JFIF APP0 units=1 означает dpi, units=2 — dots/cm, конвертация в dpi умножением на 2.54.
- PNG: pHYs хранит пиксели на метр; при unit=1 значение переводится в dpi умножением на 0.0254. При unit=0 физическая единица не определена.
- BMP: поля X/Y pixels per meter из BITMAPINFOHEADER конвертируются в dpi умножением на 0.0254. Нулевые поля означают, что разрешение в файле не задано; приложение это указывает явно.
- PCX: горизонтальное и вертикальное разрешение читаются из байтов 12–15 заголовка.
- TIFF: вручную читается первый IFD; теги 282/283 — XResolution/YResolution (RATIONAL), тег 296 — ResolutionUnit (2=дюймы, 3=сантиметры; при отсутствии применяется значение TIFF по умолчанию 2).
- GIF: формат не содержит стандартного поля физического DPI; показывается «не задано».

## TIFF IFD
Парсер проверяет порядок байтов II/MM, magic 42, смещение IFD, количество записей, тип и count каждого тега, внешние смещения значений и границы файла. Считываются ширина (256), высота (257), глубина (258), компрессия (259), число образцов (277), X/YResolution (282/283), ResolutionUnit (296) и другие структурные теги. Поддерживается Classic TIFF, не BigTIFF.

## Набор проверок
Архив `Lab2_parser_test_files.zip` содержит корректные JPEG/PNG с DPI, TIFF с разными значениями тегов, JPEG без EOI, PNG без IEND, текстовый файл с расширением JPG и усечённый TIFF. Результаты следует проверить в браузере перед сдачей; разные файлы и браузеры могут отличаться по метаданным.
