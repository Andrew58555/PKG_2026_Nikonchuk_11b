## 1. Цель

Разработано веб-приложение для чтения основной информации о растровых графических файлах: имени, размера в пикселях, разрешения, глубины цвета и параметров сжатия. Работа выполняется без сторонних библиотек для получения метаданных.

## 2. Поддерживаемые форматы

Реализованы ручные побайтовые парсеры:

- JPEG/JPG — SOI, сегменты, SOF, JFIF и проверка EOI;
- GIF — GIF87a/GIF89a, Logical Screen Descriptor, глобальная таблица цветов и Trailer;
- TIFF — Classic TIFF, byte order II/MM, IFD и теги ImageWidth, ImageLength, BitsPerSample, Compression, PhotometricInterpretation, SamplesPerPixel, XResolution, YResolution, ResolutionUnit;
- BMP — BITMAPFILEHEADER, BITMAPINFOHEADER, размеры, глубина, BI_RGB/BI_RLE4/BI_RLE8 и другие коды компрессии, палитра;
- PNG — сигнатура, IHDR, pHYs и IEND;
- PCX — заголовок 128 байт, размеры, DPI, planes, bytes-per-line и RLE.

## 3. Почему сторонние библиотеки не используются

Метаданные не извлекаются через PIL, Image, System.Drawing, sharp, exiftool или другие готовые парсеры. Браузерный File API используется только как механизм доступа к байтам выбранного пользователем файла. Сам анализ выполняется функциями `parseJPEG`, `parseGIF`, `parseTIFF`, `parseBMP`, `parsePNG`, `parsePCX`.

Для отображения собственно изображений библиотека вообще не нужна; в данной версии основная задача — чтение метаданных.

## 4. Слои архитектуры

### Presentation Layer (UI)

`index.html`, `style.css`, `app.js`.

Слой отвечает за таблицу, фильтры, прогресс-бар, статистику, экспорт CSV и выбор папки. UI не выполняет байтовый разбор.

### Core / Business Logic Layer (Engine)

`app.js` организует очередь файлов и распределяет задачи между Web Workers. Количество Workers ограничено числом логических процессоров (не более 8). После завершения одной задачи Worker получает следующую.

### Data / Parsing Layer (Infrastructure)

`worker.js` содержит ручные побайтовые парсеры форматов. Worker получает `File`, читает только нужные диапазоны через `Blob.slice().arrayBuffer()` и возвращает структурированный результат.

## 5. Потоковое чтение и быстродействие

Файл не загружается целиком в память. Для заголовков используется `File.slice()`. Для JPEG дополнительно читаются последние 2 байта для проверки EOI. Для TIFF считываются IFD и только необходимые данные тегов. После получения метаданных файл больше не удерживается парсером.

Такой подход предназначен для больших папок и не зависит от общего размера JPEG-файлов. Обработка выполняется в Web Workers, поэтому основной поток браузера остаётся доступным для интерфейса.

## 6. Обнаружение повреждённых и подменённых файлов

Проверяются:

- сигнатуры форматов (Magic Numbers);
- границы структур и чанков;
- PNG: наличие IHDR и IEND;
- JPEG: наличие SOF и EOI (`FF D9`);
- GIF: наличие Trailer;
- BMP: корректность DIB, размеров и pixel offset;
- TIFF: byte order, magic 42, IFD offset и границы тегов;
- PCX: ключевые поля заголовка и размеры.

Если расширение файла не соответствует содержимому, программа ориентируется на фактическую сигнатуру. Например, текстовый файл, переименованный в `.jpg`, не будет принят за JPEG.

## 7. Где берутся основные характеристики

**Размер:** поля ширины и высоты соответствующего заголовка/тега.

**Разрешение:** JPEG JFIF, PNG pHYs, BMP pixels-per-meter, PCX HDPI/VDPI, TIFF XResolution/YResolution + ResolutionUnit. Для GIF стандартного DPI в заголовке нет, поэтому выводится «—».

**Глубина цвета:** bits-per-pixel, bit depth или BitsPerSample/SamplesPerPixel в зависимости от формата.

**Сжатие:** поле/тег Compression или специфика формата. Например, BMP использует BI_RGB/BI_RLE4/BI_RLE8, TIFF — тег 259, PNG — Deflate, JPEG — DCT, GIF/PCX — LZW/RLE соответственно.

## 8. Запуск

1. Создать репозиторий на GitHub.
2. Загрузить в корень репозитория `index.html`, `style.css`, `app.js`, `worker.js`.
3. В GitHub открыть **Settings → Pages**.
4. В качестве источника выбрать ветку `main` и папку `/ (root)`.
5. Открыть выданный GitHub Pages URL.
6. Нажать **«Выбрать папку»** и выбрать каталог с тестовыми файлами.

## 9. Проверка

Для проверки используется архив `Для проверки Lab2`, предоставленный для лабораторной работы. Основная проверка должна включать BMP и дополнительно файлы JPG/GIF/TIFF/PNG/PCX.

Интерфейс позволяет отфильтровать повреждённые файлы и экспортировать результаты в CSV.
