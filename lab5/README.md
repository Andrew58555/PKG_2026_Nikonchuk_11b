# Лабораторная работа № 5

**Тема:** алгоритмы отсечения отрезков и многоугольников.

Веб-приложение написано на HTML, CSS и JavaScript без сторонних пакетов. Работает на GitHub Pages и не требует сборки или серверной части.

## Открытие на GitHub Pages

1. Положить содержимое этой папки в `lab5/` репозитория.
2. Если GitHub Pages уже публикует ветку `main` из корня, сайт откроется по адресу:
   `https://andrew58555.github.io/PKG_2026_Nikonchuk_11b/lab5/`
3. Войти в раздел «Рабочая область», выбрать алгоритм, перетащить окно мышкой, проверить результат.
4. Нажать «Запустить измерения» внизу страницы для нового benchmark непосредственно на текущем компьютере.
5. Отчёт открывается по ссылке «Отчёт» в шапке сайта (`REPORT.pdf`).

Чтобы запустить локально, лучше использовать HTTP-сервер из папки `lab5` (например, `python -m http.server 8000`), затем открыть `http://localhost:8000/`. Модульные Web Workers требуют корректной HTTP-отдачи модулей.

## Как пользоваться

**Отрезки.** Выбрать Сазерленда — Коэна, Лианга — Барски, метод средней точки или Сайруса — Бека для выпуклого отсекателя. Можно загрузить `.txt` со строками:

```text
3
-15 0 15 0
0 -12 0 12
-14 -10 12 11
-8 -6 8 6
```

Первая строка — число отрезков, далее по четыре координаты на строку, в конце — прямоугольное окно. Пример правильного файла: `example_segments.txt`.

Для небольшого набора можно перетаскивать мышкой конечные точки отрезков; окно также можно двигать мышью. Колесо мыши меняет масштаб, перетаскивание фона двигает координатную плоскость. Для режима Сайруса — Бека используются введённые вершины выпуклого отсекателя.

**Многоугольники.** Можно выбрать выпуклый или вогнутый многоугольник, фигуру с отверстием или самопересечение. Координаты вершин вводятся в поле, каждая строка — `x y`. Пустая строка отделяет второй контур. При вложенном контуре используется правило чётности (even-odd). Кнопка «Добавлять вершины» позволяет рисовать свой контур точками на холсте.

**Большая сцена.** В поле «Количество случайных отрезков» указать 500000 и нажать «Создать». Программа строит Quadtree порциями, чтобы не блокировать страницу. На синем фоне отображается визуальная *выборка до 24 000 исходных отрезков* (для скорости); поиск и точное отсечение выполняются по **всем** 500 000 отрезкам без выборки. Полный результат внутри окна показывается зелёным.

**Эксперимент.** Отдельный Web Worker обрабатывает 500000 отрезков при 100 положениях окна, сравнивает Quadtree разной глубины, полный перебор и наборы разной плотности. Измеряется геометрическая обработка без UI; данные графиков можно экспортировать в CSV. Значения зависят от процессора и браузера.

## Допуск и особенности реализации

- Численные геометрические проверки выполняются с `ε = 10⁻⁷` и координатами двойной точности (`Float64Array`).
- Для простого прямоугольного отсекателя доступны структурный и параметрический алгоритмы, дополнительно метод средней точки.
- Для выпуклого многоугольного отсекателя реализован Сайрус — Бек.
- Для сложных многоугольников применяется топологический метод разбиения рёбер и обхода ориентированных граничных цепочек по идее Уайлера — Атертона. Он поддерживает примеры вогнутых контуров, отверстий и самопересечений без растрового отсечения.
- 4-битная маска AABB отбрасывает невозможные пересечения. Quadtree хранит каждый сегмент в одном узле; длинные сегменты остаются в родительских узлах, без копирования во все дочерние.
- Quadtree ускоряет выборку при удачном распределении данных, но в худшем случае может потребовать O(N) проверок. Параметры индекса сравниваются экспериментально.
- 60 FPS зависит от оборудования и размера окна, поэтому фактическую частоту показывает пользовательский интерфейс при перетаскивании; её нельзя гарантировать для всех устройств.

## Локальные проверки (без установки зависимостей)

При наличии Node.js 20+:

```bash
npm test
npm run benchmark
```

`npm test` запускает 21 проверку, включая сверку Сазерленда — Коэна и Лианга — Барски на 10 000 случайных отрезков и сверку Quadtree с полным перебором на 200 окнах.

Подготовленный контрольный результат лежит в `report_assets/benchmark-results.json`. При открытии сайта эти числа **не подставляются** вместо измерений: benchmark сайта выполняет новые запуски в браузере. Результаты в отчёте относятся к конкретному запуску Node.js, указанному в таблице методики.
