# ЛР1 — вариант 4: RGB ↔ HSV ↔ LAB (HTML + CSS + JavaScript)

Веб-приложение для лабораторной работы по цветовым моделям. Реализовано на **чистом JavaScript** без библиотек конвертации цветов, без NumPy/OpenCV/colorsys и без фреймворков.

## Что реализовано

- одновременно отображаются RGB, HSV и LAB;
- точный числовой ввод для каждой компоненты;
- плавное изменение через 9 слайдеров;
- нативная цветовая палитра в каждой панели;
- автоматический пересчет двух остальных моделей;
- динамические градиенты с учетом текущих остальных компонент;
- D65 / D50 / E;
- RGB↔XYZ-матрица **строится программно** из xy-координат sRGB primaries и выбранной точки белого;
- собственные операции с 3×3-матрицами, включая обращение;
- Clipping и Scaling для LAB-цветов за пределами gamut sRGB;
- предупреждение о gamut и вывод исходного линейного RGB;
- архитектура Model / View / Controller;
- 28 автоматических микро-тестов на встроенном `node:test`.

> Требование UCR/GCR относится только к вариантам, где рассчитывается CMYK. В варианте 4 модель CMYK отсутствует, поэтому UCR/GCR не добавлялись искусственно.

## Запуск

Нужен Node.js 20+ только для локального HTTP-сервера и тестов. Само приложение выполняется браузером.

```bash
npm start
```

Открыть:

```text
http://localhost:4173
```

Также проект можно без сборки разместить на GitHub Pages: корнем публикации должна быть папка, где лежит `index.html`.

## Тесты

```bash
npm test
```

Ожидаемый итог:

```text

```

Среди проверок есть обязательный пример:

```text
RGB(255, 0, 0)
→ HSV(0°, 100%, 100%)
→ LAB ≈ (53.24, 80.09, 67.20) при D65
```

Дополнительно проверяются обратимость RGB↔HSV, LAB↔XYZ, RGB↔XYZ для D65/D50/E, динамическое построение матрицы, Clipping/Scaling и выход из gamut.

## Логика преобразований

Основные маршруты:

```text
RGB ↔ HSV
RGB ↔ XYZ ↔ LAB
```

XYZ используется как внутреннее пространство между RGB и LAB. Для RGB→XYZ сначала выполняется обратная gamma-коррекция sRGB. Для XYZ→RGB после матричного преобразования применяется Clipping или Scaling, затем прямая gamma-коррекция.

### Динамическая RGB→XYZ-матрица

Готовые матрицы в коде отсутствуют. Хранятся только xy-координаты первичных цветов sRGB и xy выбранного источника света.

1. Каждый primary переводится из xy в XYZ при `Y=1`.
2. Из векторов строится матрица `P`.
3. Вычисляется белая точка `W` из xy выбранного D65/D50/E.
4. Решается `S = P⁻¹W`.
5. Формируется `M = P · diag(S)`.
6. `M⁻¹` вычисляется собственной функцией `inverse3()`.

При выборе другого источника `ColorConverter.setIlluminant()` строит новый контекст и новую пару матриц.

## Архитектура

- **Model** — только математика и данные преобразований, не работает с DOM.
- **View** — только элементы страницы, ввод/вывод и визуальное представление.
- **Controller** — принимает события View, вызывает `ColorConverter`, обновляет интерфейс и динамические градиенты.

Controller хранит исходную модель последнего ввода. Поэтому при переключении `Clipping ↔ Scaling` исходный LAB пересчитывается заново, а не используется уже обрезанный RGB.

## Что показать на защите

1. Ввести `RGB(255, 0, 0)` и показать HSV/LAB.
2. Подвигать R/G/B и показать изменение градиентов других слайдеров.
3. Переключить `D65 → D50 → E`: меняются точка белого, LAB и отображаемая RGB→XYZ-матрица.
4. Ввести `LAB(50, 127, 127)`: появится предупреждение о выходе за gamut.
5. Переключить `Clipping ↔ Scaling`: итоговый RGB изменится.
6. Показать разделение `src/model`, `src/view`, `src/controller`.
7. Запустить `npm test` и показать 28/28 успешно пройденных тестов.

## Автотесты без Node.js

Если Node.js/npm не установлен, тесты можно запускать прямо в браузере. Из корня проекта запустите обычный Python HTTP-сервер:

```bash
python -m http.server 8000
```

Затем откройте:

- приложение: `http://localhost:8000/`
- автотесты: `http://localhost:8000/tests/`

Страница тестов импортирует те же файлы из `src/model`, которые использует приложение. Node.js, npm и сторонние тестовые библиотеки для этого режима не нужны. На странице выполняются 28 микро-тестов для HSV, LAB, RGB↔XYZ, динамических матриц D65/D50/E, матричных операций, Clipping/Scaling и интеграционного `ColorConverter`.
